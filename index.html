ENGINEER / PRODUCT DESIGNER

真面目に、単刀直入に、
丁寧でありたいです。

大切にしていることが伝われば、それで十分だと思っています。志のある方の実現を、実装と体験の両方から支えたいです。

Yoshinori Ito 福岡市 基本情報技術者

僕について

30歳手前まで飲食や現場の仕事などをしていて、そこから未経験で Web に入りました。PHP と Laravel で実装を積み、テックリードを経験したあと、自分からデザインの側にも寄っていき、いまは業務委託として、要件を取り込むかどうかの判断から UI と実装までを一人で見ています。人の話はできるだけ最後まで聞くようにしていて、短絡的に聞こえることでも、その人の意図や人となりを想像しながら補って受け取りたいと思っています。今できることや責任の範囲は環境や時点で違うので、それをその人の能力の結論にはせず、それでもはっきり違うと感じたときは、相手を下げない形で伝えるようにしています。

判断するときは、動くかどうかより、使われるか、あとから保守しやすいか、今の納期や予算に対して量として適切かを見ていて、分からないことは手を動かさないと情報が増えないので、まずやってみることが多いです。ただ、やみくもに増やすのではなく、やりたいことを進めるために本当に必要なものだけを置く、という感覚で、仕事を選ぶときも、一緒にいる人の人柄と自分が当事者になれるかを大切にしています。拡大や成果を急いだ結果、人とチームが疲弊していく現場も見てきたので、規模が必要なプロダクトもあるとは思いながら、そうでないものまで無理に大きくしなくてもいい、というのが今の気持ちです。

大切にしていること

敬意を先に置く

特定の誰かを尊敬している、というより、人として先に敬意を置きたいタイプです。話が雑に聞こえても、肯定的な意図がある前提で聞くようにしています。違うと思ったときは直接伝えます。高圧的なやりとりが続いた現場からは、静かに離れました。

必要な量を考える

安易な実装は、できるだけ避けています。あとで誰が保守するのか、本当に使われるのかを先に考えます。見当がつかないときは、情報を得るために小さく始めることが多いです。納期と予算の範囲で、伝えるために必要なところまでにする、という感覚です。

実装から体験まで見てきたこと

最初から得意分野があったわけではありません。サーバー、フロント、決済、CMS、独自のフレームワークなど、確かな型がなかった分、いろいろなものを触ってきました。デザインでは UI/UX に加えて、マーケやブランドの話も本やポッドキャストで追っています。深くないことは、深くないと言います。

人とチームが続くか

売上や規模が、いつも最優先だとは思っていません。プロダクトによって、ちょうどいい大きさがあると考えています。PayPay や LINE のように、規模がないと成立しないものもあります。らくばるは、どちらかというとそうではありません。無理な拡大でチームやプロダクトが傷つく様子は、リトル・ママ、エール、ザッパラスで見てきました。

弱いところもあります。気持ちが乗らないと着手が遅れがちです。一人で進めるのは向いていますが、放置されるとスケジュールが雑になります。一度手をつけると進みますし、相談できる人がいると立て直しやすいです。

技術

バックエンド PHP / Laravel（10年以上）。詳細仕様のない状態からの設計〜実装。管理画面、API、分析、通知、PDF 出力。
フロント HTML / CSS / JS（10年以上）。Vue / Nuxt。WordPress カスタマイズから、案件ごとに表だけ差し替える横展開まで。
いま Flutter / Flutter Web。サービスデザインから UI、実装まで一人。Cursor による AI 開発。
インフラ AWS と GCP。構築、ミドルウェア、パフォーマンス、セキュリティ。らくばると自作の診断アプリは GCP。ユーザー情報の扱いなど、元エンジニアとしての指摘。
デザイン UI/UX。Figma / Adobe XD。ユーザーインタビューからプロダクトへの落とし込み。エンジニアが実装しやすい定義への整理。
その他 MySQL、Rails（小規模実装と移管）、Perl（横展開基盤）

役に立てるなら、エンジニアリングでも UI/UX でも、そのあいだでも引き受けます。
