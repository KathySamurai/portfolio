ENGINEER / PRODUCT DESIGNER

真面目に、単刀直入に、
丁寧につくる。

万人受けは狙っていない。志のある人の実現を、実装と体験の両方から助けたい。肩書きはどうでもいい。

Yoshinori Ito 福岡市 基本情報技術者

僕について

30歳手前で未経験から Web に入った。PHP と Laravel で実装を積み、テックリードをやって、自分からデザイナーに寄った。いまは業務委託で、取り込むかどうかの判断から UI、実装まで一人で見ている。

人の話は最後まで聞く。短絡的に聞こえても、その人の意図と人となりを補って汲もうとする。能力がない、で人を切らない。子供も大人も、今の環境と責任が違うだけで、人としての結論にはしない。そのうえで、強く違うと思ったら誰にでも言う。

判断の基準は、動くかどうかじゃない。使われるか、保守できるか、今の納期と予算で適切な量か。分からないことは、やらないと情報が増えないから手を出す。ただし闇雲にはやらない。あればあるほど良い、とは思っていない。

仕事を選ぶときは、人柄と、自分が当事者になれるか。拡大や成果のために人とチームが壊れる現場は、いくつか見てきた。規模が先に立たないと成立しないものもある。でも、インフラに近いもの以外は、無理に大きくしなくていいと思っている。

丁寧にできないものは、不要だ。合わない人もいると思う。それでいい。

特徴

人を切らずに、間違いは言う

尊敬する特定の人がいる、というより、人としての敬意が先にある。能力で人を切らない。短絡的に聞こえる話も、肯定的な意図を補って聞く。そのうえで、違うと思ったら直接言う。高圧的な反応が返ってきた現場には、残らなかった。

適切な量で切る

安易な実装はしない。保守する人、保守のしやすさ、本当に使われるかを先に見る。分からない点は、予想できないならまずやって情報を取る。ただし今の納期と予算での、適切な量。やりたいことをやるために何が要るか、伝えるために何が要るかを考える。

サーバーから体験まで、同じ机に載せる

最初から得意技があったわけじゃない。サーバー、フロント、決済、CMS、独自フレームワークと、確実なスキルがなかった分、色々やってきた。デザインは UI/UX に加えて、マーケやブランドも本やポッドキャストで鮮度を保っている。深くないものは、深くないと言う。

人とチームが持つかを、拡大より先に見る

売上の最大化や規模が、すべてだとは思っていない。プロダクトに応じた規模がある。PayPay や LINE は規模がないと成り立たない。らくばるはそうではない。無理に大きくしてチームやプロダクトが壊れていくのを、リトル・ママ、エール、ザッパラスで見てきた。

癖もある。気持ちが乗るまで手がつかない。一人作業は好きだけど、放置されるとスケジュールが雑になる。着手さえすれば進む。相談できる相手がいると立て直せる。

技術

バックエンド PHP / Laravel（10年以上）。詳細仕様のない状態からの設計〜実装。管理画面、API、分析、通知、PDF 出力。
フロント HTML / CSS / JS（10年以上）。Vue / Nuxt。WordPress カスタマイズから、案件ごとに表だけ差し替える横展開まで。
いま Flutter / Flutter Web。サービスデザインから UI、実装まで一人。Cursor による AI 開発。
インフラ AWS と GCP。構築、ミドルウェア、パフォーマンス、セキュリティ。らくばると自作の診断アプリは GCP。ユーザー情報の保持など、元エンジニアとしての指摘。
デザイン UI/UX。Figma / Adobe XD。ユーザーインタビューからプロダクトへの落とし込み。エンジニアが実装しやすい定義への翻訳。
その他 MySQL、Rails（小規模実装と移管）、Perl（横展開基盤）

肩書きはどうでもいい。役に立つならエンジニアリングでも UI/UX でも、そのあいだでもやる。
